■ プロジェクト概要
  競馬予想分析システム「Enable Edge Engine」
  目的: CrossFactorを超える分析自由度を持つ、
        プロフェッショナル向け競馬データ分析プラットフォーム構築

================================================================
■ 全体のゴール
================================================================

  【最終目標】
  JRA全10競馬場・全馬券種・全距離区分における
  「統計的に有効なファクター」を特定し、
  各馬への複勝回収率スコアを自動算出するエンジンを完成させる。

  【スコアリングの仕組み】
  - 式1（固定8パターン）: コース×脚質・ペース等の普遍ルール
  - 式2（採用ファクター）: セグメント別に統計的に有効なファクター群
  - 最終スコア = 式1×0.2 + 式2×0.8

■ このセッション（前回から継続）でやったこと
================================================================

【問題発覚：KEIBAJO_SURFACEが01〜05しか存在しない】
  - スクリーニング結果を確認したところ、
    中山(06)・中京(07)・京都(08)・阪神(09)・小倉(10)が
    ファクター一覧に一切存在しないことが発覚。
  - 原因調査の結果：factor_screening.py の
    DEFAULT_CEO_ROWS = 100_000 （LIMIT 10万行）が原因と特定。
  - DBの物理順序でLIMITをかけると東京(01)〜新潟(04)付近で
    10万行に達し、それ以降の競馬場データが読み込まれなかった。

【修正内容】
  ファイル: backend/batch/factor_screening.py
  変更: DEFAULT_CEO_ROWS = 100_000
     → DEFAULT_CEO_ROWS = 0  # 0 = 無制限（全競馬場カバーのため）

  ※ ORDER BY追加も試みたが、456,615行+JOIN のソートで
    数時間かかる致命的な遅延が発生したため削除。
    LIMIT=0（全件）なのでORDER BYは不要と判断。

【--skip-phase1 フラグ追加】
  Phase1（1.5時間）を再実行せずに既存CSVを再利用できる
  フラグを追加。Phase2・CEOのみ再実行可能に。
